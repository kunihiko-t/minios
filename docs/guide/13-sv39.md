# 13. Sv39と単一アドレス空間

## 学習目標

**Sv39**が39ビットの仮想アドレスを三段のページテーブルで4 KiBの物理ページへ変換する仕組みを説明できるようになります。
仮想ページ番号の`VPN[2]`、`VPN[1]`、`VPN[0]`を順に使うpage walkと、**ページテーブルエントリー（PTE）**の`R`、`W`、`X`、`U`権限を対応づけます。
`satp`へroot PPNと`MODE=8`を書き、直後の`sfence.vma`で古い変換結果を破棄する理由も確認します。

## 背景

起動直後のCPUは、命令やデータのアドレスを物理アドレスとして扱うbareモードで動きます。
bareモードは起動処理を短くできますが、カーネルとユーザープログラムへ異なる権限を与えられません。

そこでMiniOSは、カーネルの実行位置を変えない**カーネル恒等写像**を作ってからSv39へ切り替えます。
仮想アドレスと物理アドレスを同じ値にしておけば、切り替え中の命令位置、起動用スタック、トラップベクター、UARTへ同じアドレスで到達できます。
ただし同じ値であることは同じ権限であることを意味せず、`.text`は`R+X`、`.rodata`は`R`、書き込み領域とUARTは`R+W`、すべて`U=0`です。

## 実装

`kernel::vm::address`は、Sv39のbit 38をbit 63まで符号拡張した正規仮想アドレス、4 KiB境界、VPN、PPNを型の生成時に検査します。
`kernel::vm::pte`はbranchとleafを区別し、書き込みだけのleafと`W+X`のleafを拒否します。

アドレス空間の構築では、`AddressSpaceBuilder`がrootページテーブル、中間ページテーブル、新しく写像したページを`AddressSpaceStorage`へ記録します。
この固定容量の所有権表により、汎用ヒープがなくても構築途中の失敗時に確保済みフレームを逆順で返せます。
カーネルのセクションとUARTが占有する物理フレームは借用した写像として扱うため、ページテーブルの所有フレームと混同しません。

`KernelMapPlan`はリンカーが公開した各セクション、管理対象RAM、UARTをS-mode専用で恒等写像し、boot payloadの`0x8780_0000..0x8800_0000`を写像しません。
`kernel_main`はこの計画から**activeなカーネルアドレス空間**を完成させ、root PPNを`satp`へ設定した直後に`sfence.vma`を実行します。
activeな空間は以後のカーネル実行に使うため、`kernel_main`の残りの処理中も所有権を保持します。

[Sv39と実行前ELFロードの構成図](../assets/sv39-loaded-image-architecture.html)は、activeなカーネル空間と次章で作るinactiveなユーザー空間の違いを示します。
図では三段page walkと個々の失敗分岐を省き、その詳細をこの章と次章へ残しています。

## 実行と確認

activeな写像と権限をQEMU上で確認するには、リポジトリのルートで次のコマンドを実行します。

```console
$ cargo xtask test vm
...
[MINIOS_TEST] vm: ok
```

`vm`経路は`.text`、`.rodata`、`.data`と`.bss`、起動用スタック、UARTの全ページをwalkし、物理アドレスと`R/W/X/U`をリテラルの期待値と比較します。
続いて`0x8780_0000`が`NotMapped`であることを調べ、すべて一致した場合だけ`[MINIOS_TEST] vm: ok`を出します。
このマーカーはU-modeの実行成功を示さず、S-modeからactiveなカーネル写像を観測できたことだけを示します。

## よくある失敗

- 非正規な仮想アドレスを受け入れる：bit 38の符号拡張と一致しない値は`AddressError::NonCanonical`として拒否します。
- `W`だけのPTEを作る：RISC-Vでは`R=0, W=1`が予約済みなので、`PageFlags`の生成時に拒否します。
- `satp`の切り替え前に必要な写像をそろえない：実行中の命令、スタック、トラップベクター、UART、ページテーブルを初期化するRAMのどれかが欠けると、切り替え直後に処理を継続できません。
- boot payloadを恒等写像する：予約領域をmanaged RAMに含めると、後続のMiniBundleとフレーム割り当てが同じ物理ページを所有したと誤認するため、アロケーター上端とカーネル写像の両方を`0x8780_0000`で止めます。

## 演習

まず`cargo test -p minios-kernel vm:: --locked`を実行し、ホスト上のpage walk試験が成功することを確認してください。
次に試験用のPTEを一つだけ別の物理ページへ向け、`translate`が期待した不一致を返す試験を追加してください。
別の試験ではカーネル用leafの`U`を立て、権限比較が失敗することを確認してから変更を戻します。
最後に`cargo xtask test vm`へ戻り、ホスト試験だけでは観測できない`satp`切り替え後の写像を検査してください。
