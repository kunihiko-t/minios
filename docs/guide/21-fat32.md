# 21. FAT32の読み書き

## 学習目標

boot sectorのBPBをaddress計算の前に検証し、volume外参照と無限loopを防ぐ理由を説明できるようになります。
cluster chain、directory entry、VFATのlong file name (LFN) がどう対応するかを追います。
`/`区切りのpath解決から、file作成、write、unlink、rename、mkdir、rmdirまでの書き込み経路を確認します。
同じparserがNEORV32のread-only SD経路でも使われることを確認します。

## 背景

[第20章](20-virtio-blk.md)のvirtio-blk driverは、512 byteのsectorを読み書きする口だけを提供します。
fileやdirectoryという単位は、その上でdisk上のFAT32構造を解釈する層が作ります。

FAT32 volumeは、先頭のboot sector、FAT (File Allocation Table)、data領域の三つから成ります。
data領域は**cluster**という単位で区切られ、FATの各entryは「このclusterの次はどのclusterか」を表します。
fileやdirectoryの中身は、先頭clusterからFATをたどる**cluster chain**として表現され、`0x0fff_fff8`以上の値が終端 (EOC) です。
これらの値は外部入力であり、壊れていればvolume外の参照や終わらないchainを生みます。

directoryの中身は32 byteのrecordの列です。
通常のrecordは8.3形式の名前、attribute、先頭cluster、byte sizeを持ちます。
8.3に収まらない名前は、直前に置かれたattribute `0x0f`のLFN recordの列が13文字ずつ運びます。

## 実装

### BPBの検証とmount

[`Fat32::mount`](../../kernel/src/storage/fat32.rs)は最初にLBA 0をboot sectorとしてparseし、成功すればpartitionなしのsuperfloppyとしてmountします。
失敗した場合は`55aa`署名付きMBRを要求し、四つのprimary entryから最初の`0x0b`または`0x0c` partitionを選びます。
GPTのprotective MBR (`0xee`) と拡張partitionは`Unsupported`で拒否します。

`parse_boot_sector`は、sector長512 byte、2の冪かつ128以下のsectors per cluster、FAT数1か2を要求します。
FAT12とFAT16は、root entry数とFAT16 sizeが0でないこと、またはdata cluster数が65,525未満であることで見分け、`Unsupported`を返します。
FAT領域とdata領域の端は`checked_add`と`checked_mul`で計算し、volume末尾を越えれば`InvalidFilesystem`です。

検証済みの値だけが`Fat32`のfieldになります。
以後の`data_sector_lba`と`next_cluster`は、cluster番号が`2..data_cluster_count + 2`に入るかを毎回確かめます。
chainを歩くloopは読んだcluster数を`data_cluster_count`で打ち切り、循環するchainを`CorruptChain`として報告します。

### directory entryとLFN

`walk_dir`はdirectory chainをsector単位で読み、先頭byteが`0x00`のrecordで走査を終えます。
`0xe5`は削除済みrecordで、LFNとshort entryの対応をそこで切ります。
`.`と`..`は`parse_dir_entry`が名前の検査で除くため、列挙にもpath照合にも現れません。

LFN recordは`PendingLfn`が順番号の連続性を検査しながら蓄えます。
直後のshort entryで、raw 8.3名から計算した`lfn_checksum`がLFN側のchecksumと一致した場合だけ、長い名前を表示名に採用します。
一致しなければ`LONGFI~1.TXT`のような8.3名のまま扱います。

### path解決

`resolve_path`は`/`で区切った各要素を、diskへ触れる前に`is_valid_component`で検査します。
空要素、`.`、`..`、`\`を含む要素、255 byteを超える要素は、存在の有無に関係なく`InvalidName`です。
その後rootから一要素ずつ`find_entry_in`で探し、途中の要素がfileなら`NotDirectory`を返します。

照合を行う`matches_component`は、LFN表示名とのASCII大小文字無視の比較と、8.3へ正規化した名前の比較を両方試します。
このため`cat Long File Name.txt`と`cat LONGFI~1.TXT`は同じfileを指します。

### 作成と書き込み

write APIは[`kernel/src/storage/fat32.rs`](../../kernel/src/storage/fat32.rs)の、`SectorReader + SectorWriter`を要求するimpl blockにまとまっています。
`SectorWriter` traitは[`kernel/src/storage/mod.rs`](../../kernel/src/storage/mod.rs)で定義します。
`SectorWriter`はRV32では構成されないため、NEORV32 buildにはwrite経路自体が含まれません。

`create_file`は最終要素を`to_short_name`で8.3へ正規化し、変換できない名前を`InvalidName`で拒否します。
同じraw 8.3名のfileがあれば内容を保ったまま`FileDesc`を返し、無ければ`find_free_dir_slot`で空きslotを探してrecordを書きます。
空きslotは`0xe5`の削除跡を優先し、終端の`0x00` slotを使った場合は`place_dir_entry`が次のrecordへ終端を移します。

`write_range`は`offset > size`の穴あきwriteを`InvalidOffset`で拒否します。
`ensure_capacity`が必要なcluster数までchainを延ばし、`alloc_cluster`はFATを先頭から走査して値0のentryにEOCを書き、clusterをzero-fillします。
端数のsectorだけをread-modify-writeし、最後に`sync_dir_entry`が先頭clusterとsizeをdirectory recordへ書き戻します。

### unlinkとrmdir

`unlink_file`はdirectoryを`IsDirectory`で拒否し、書き込みの前に`chain_tail`でchain全体を検証します。
破損していればentryもFATも変更せずに`CorruptChain`を返します。
検証後、`lfn_run_bounds`でentry直前のLFN record列を特定し、`mark_deleted_range`でその列とentryの先頭byteを`0xe5`にしてから、`free_chain`でFATを0へ戻します。

`remove_dir`は同じ手順を使い、`.`と`..`以外のentryが一つでもあれば`NotEmpty`を返します。
`create_dir`は新しいclusterを確保して`.`と`..`を書いてから親のentryを書きます。
親がrootの場合、`..`の先頭clusterはFAT32の規約に従い0です。

### rename

`rename`は新しい親directoryがsourceと同じなら`rename_in_place`を使い、旧LFN record列を消してからrecord内の名前11 byteを書き換えます。
entryの物理位置が変わらないため、開いているfdはそのまま有効です。

別directoryへの移動では、書き込みの前に全検証を済ませます。
directoryを自身や子孫の中へ移す指定は、`check_move_not_into_self`が新しい親から`..`をrootまでたどって`MoveIntoItself`で拒否します。
`check_rename_target`はfileからdirectoryへの置換を`IsDirectory`、directoryからfileを`NotDirectory`、空でないdirectoryへの置換を`NotEmpty`で拒否します。
検証後に旧record列を消し、置換対象を削除し、新しいslotへrecordを複写し、directoryなら`update_dotdot`で`..`を新しい親へ書き換えます。

戻り値の`RenameOutcome`は、移動した場合の新旧位置を`moved`に、置換で消えたentryの位置を`replaced`に持ちます。
fd tableはこれを使ってwrite-back先の追従と失効を行います。

### FSInfoとFATの複製

この実装はFSInfo sectorを読まず、更新もしません。
FATの読み出しは一面目だけを使います。
`set_fat_entry`は一面目のsectorを書き換えたあと、同じsectorを`fat_count`面すべての同じ位置へ書きます。
二面目の位置は一面目のLBAに`fat_sectors`を足したもので、この計算も`checked_mul`と`checked_add`で行います。
一面目を書いた後に二面目の書き込みが失敗するとエラーを返しますが、一面目は戻さないため、二つのFATは食い違ったまま残ります。
FSInfoの整合性は[ロードマップ](../reference/roadmap.md)の残課題です。

### shellとNEORV32のSD経路

RV64 shellの`ls`、`cat`、`rm`、`mkdir`、`rmdir`、`mv`は、[`kernel/src/shell/mod.rs`](../../kernel/src/shell/mod.rs)で最初の使用時にvirtio-blkをprobeしてmountし、それぞれ`for_each_entry`、`read_file`、`unlink_file`、`create_dir`、`remove_dir`、`rename`へ委ねます。
`rm`、`mkdir`、`rmdir`、`mv`は成功時に何も出力しません。
どのcommandも、失敗は`print_fat_error`が`virtio: directory not empty`のような診断へ写像します。
[`parse_command`](../../kernel/src/shell/command.rs)は`mv`の引数を最初の空白で二分するため、`mv`の引数に空白は使えません。

NEORV32の[`SdCard`](../../kernel/src/storage/sd.rs)は`SectorReader`だけを実装し、同じ`Fat32::mount`でvolumeを開きます。
RV32 shellは`for_each_root_entry`と`read_root_file`だけを使い、root直下の8.3名に限定されます。
`PendingLfn`はRV32ではno-opの型に置き換わり、path解決もbuildされないため、IMEMの予算に収まります。
設計の詳細は[NEORV32 read-only FAT32設計](../reference/sd-fat32.md)にあります。

## 実行と確認

QEMU testは、[`xtask/src/disk.rs`](../../xtask/src/disk.rs)が毎回作る決定的なFAT32 imageをvirtio-blkとして接続します。
次のコマンドは、guestが`read_file` syscallで`DOCS/NOTE.TXT`をpath指定のまま読み、stdout frameとして`note inside docs`を返すことを確認します。

```console
$ cargo xtask test file
...
MiniOS payload: ok code=42
summary: PASSED all 1 phases (elapsed: ...)
```

書き込み経路は、それぞれ別のguestで確認します。

```console
$ cargo xtask test file-write
$ cargo xtask test file-unlink
$ cargo xtask test file-rename
$ cargo xtask test file-mkdir
```

host harnessはReady、spawn通知、stdout、Exit (code 42)、回収diagnosticのcontrol frame列を完全一致で照合します。
stdoutはそれぞれ`written by guest`、`file removed`、`rename verified`、`mkdir verified`です。
`file-rename`のguest ([`guest/src/bin/file_rename.rs`](../../guest/src/bin/file_rename.rs)) は、fdの継続、置換されたfdの`EBADF`、cross-directory移動、cycle拒否を検査し、どれかが外れると70で終了します。

shellのcommandは`cargo xtask test shell`が入力列を送り、transcriptを行単位で照合します。

```console
$ cargo xtask test shell
...
minios> cat Long File Name.txt
long file contents
...
minios> rmdir DOCS
virtio: directory not empty
...
summary: PASSED all 1 phases (elapsed: ...)
```

## よくある失敗

- BPBの値でそのままaddressを計算する：overflowやvolume外のLBAが生じるため、`checked_add`と`checked_mul`でvolume末尾と比較してからfieldに採用します。
- chainのloopに上限を置かない：FATの循環で走査が終わらないため、読んだcluster数を`data_cluster_count`で打ち切ります。
- 長い名前でfileを作ろうとする：`create_file`、`create_dir`、`rename`の新名は8.3だけを受理し、`long name.txt`は`InvalidName` (guestでは`EINVAL`) になります。
- LFNを持つfileを`mv`して長い名前が残ると期待する：renameは旧LFN record列を消して8.3名だけを書くため、移動後の表示名は8.3名です。
- 書き込みの途中で検証する：unlinkやrenameでchain破損を書き込み後に見つけると半端な状態が残るため、`chain_tail`と`read_dotdot`を最初に呼びます。
- FATを一面だけ更新する：FAT数2のvolumeで二面目を放置するとhost側の`fsck`がFAT間の差分を報告するため、`set_fat_entry`は全面の同じ位置へ同じsectorを書きます。
- FSInfoが更新されると思い込む：この実装はFSInfoの空きcluster数を書き換えないため、host側の`fsck`はその値の不一致を報告し得ます。

## 演習

[`kernel/src/storage/fat32.rs`](../../kernel/src/storage/fat32.rs)のhost testを参考に、FATの二つのclusterが互いを指す循環chainを作り、`read_file`が`CorruptChain`を返すことを確認してください。
試験後は`cargo test -p minios-kernel storage::fat32 --locked`を実行します。

`set_fat_entry`は二面目の書き込みに失敗すると、二つのFATが食い違ったまま残ります。
mount時に全FAT面を比較し、食い違っていれば`InvalidFilesystem`を返す検査を追加してください。
NEORV32 buildのIMEMを圧迫しないよう、検査はRV32以外でだけ構成します。
host testでは`mirrored_sectors`で二面目のFATを1 byte書き換え、mountが失敗することを確かめます。
変更後に`cargo xtask test file-write`が通ることも確認します。
