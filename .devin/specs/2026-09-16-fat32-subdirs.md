# FAT32 subdirectory traversal + shell path arguments

## 目的

`Fat32`をroot directory専用から階層directoryへ拡張し、shellの`ls`/`cat`が
`/`-区切りのpathを受け付けるようにする。RV64（virtio-blk）とRV32（SD）の
両targetで同じparser・同じshell経路を使う。

## 設計

### parser（`kernel/src/storage/fat32.rs`）

- `walk_root`を`walk_dir(cluster)`へ一般化する。rootは`walk_dir(root_cluster)`、
  サブディレクトリは`walk_dir(entry.first_cluster)`。directoryデータの形式は
  階層によらず同じで、既存のcluster-chain走査・bounded loop・corruption検査を
  そのまま再利用する。
- `find_root_entry`を`find_entry(dir_cluster, wanted)`へ一般化。
- `resolve_path(path) -> Result<DirEntry, FatError>`を追加。
  - pathは`/`区切り。空要素・先頭`/`・末尾`/`・`.`/`..`は`InvalidName`。
  - 各要素は既存の`normalize_input_name`（8.3、case-insensitive）で照合。
  - 最終要素以外は`directory`必須。fileへ潜ろうとしたら新規`NotDirectory`。
- APIをpath型へ改名する:
  - `for_each_root_entry(visit)` → `for_each_entry(path, visit)`
    （`""`はrootを列挙）
  - `read_root_file(name, write)` → `read_file(path, write)`
- `FatError`に`NotDirectory`を追加。`.`/`..`擬entryは従来通り`parse_dir_entry`
  が除外する（listに現れず、path要素としても受理しない）。

### shell（`kernel/src/shell/mod.rs` + `command.rs`）

- `Command::Ls`を`Command::Ls(&str)`へ変更（`""`はroot）。
- `ls PATH`：path解決→directoryなら列挙、fileなら`not a directory`。
- `cat PATH`：`/`を含むpathをそのまま`read_file`へ渡す。
- usage・エラーmessage prefix（`sd:`/`virtio:`）は従来通り。
- `NotDirectory`を`{prefix}: not a directory`へ写像。
- **RV32制約**: NEORV32の32 KiB IMEMにはpath解決（約1.8 KiB）が乗らない。
  `for_each_entry`/`read_file`/`resolve_path`を`not(riscv32)`へcfg絞り、
  RV32 shellはroot-only API（`for_each_root_entry`/`read_root_file`）を
  維持する。`/`を含む引数は`sd: invalid 8.3 name`として報告する。

### xtask（`disk.rs` + `qemu.rs`）

- deterministic imageに`DOCS/`subdirectoryと`DOCS/NOTE.TXT`を追加。
- `SHELL_SCRIPT`に`ls DOCS`と`cat DOCS/NOTE.TXT`を追加し、transcript
  verifierとfixtureを更新する。

### 所有権・非目標

- 書き込み・LFN・`.`/`..`の解決・mount中のdirectory handle保持は対象外。
- 変更は読み取り経路のみ。session所有権の構造は不変。
