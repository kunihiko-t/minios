# FAT32 unlink（file削除 + fd失効）

## 目的

guestが`unlink`でfileを削除できるようにする。dir entryの`0xe5`化、
LFN record列の一括削除、cluster chainの解放、そして開いているfdの
失効までを一つの操作として設計する。

## ABI（`abi/src/syscall.rs`）

- `SyscallNumber::Unlink = 8`: `a0=path_ptr, a1=path_len` → 0またはerrno。
  path規約は`open`/`create`と同じ（UTF-8・256 byte以下）。
  directoryは`EISDIR`、不在は`ENOENT`。

## 削除の意味論（POSIXとの差異を明記）

- dir entryとそれに先行する連続LFN record列を`0xe5`へ書き換える。
  `find_free_dir_slot`が既に`0xe5`を再利用するため、slotは即座に
  回収される。
- fileのcluster chainをFAT走査で全entry 0へ戻す（解放）。
  chainが破損していれば**何も書かずに**`CorruptChain`で失敗する
  （先に`chain_tail`で検証してからentry削除と解放を行う）。
- **fd失効**: POSIXでは開いたfdは削除後も有効だが、MiniOSはclusterを
  即時解放するため、該当entryを指す全processのfdを`unlink`時に
  無効化する（dir位置で照合）。以後の`read`/`write`/`close`は`EBADF`。
  呼び出しprocess自身のfdも失効する。

## FAT32（`storage/fat32.rs`、`not(riscv32)`）

- `DirLoc`に`dir_head`を追加（walk起点のchain head）。
- `unlink_file(path) -> Result<(u32, u32), FatError>`: resolve→dir拒否
  →`chain_tail`でchain検証→`lfn_run_start`で削除開始点を特定→
  `mark_deleted_range`でentry+LFN列を`0xe5`化→`free_chain`で
  cluster解放→削除したentryの`(dir_cluster, dir_index)`を返す。
- `free_chain`: chain検証済みの前提で各FAT entryを0へ戻す。
  `first_cluster == 0`（空file）は何もしない。
- `FileDesc::dir_location() -> (u32, u32)` accessorを公開
  （revocation照合用）。

## kernel/bin配線

- `ControlSource::unlink(path) -> Result<(), isize>`（default`ENOSYS`）。
- `dispatch_unlink`はopenと同じpath検証規約。path copyを
  `copy_user_path` helperへ切り出してopen/create/unlinkで共有する。
- `revoke_file_fds(dir_cluster, dir_index)`: 全pidの`FILE_FDS`を走査し、
  `desc.dir_location()`が一致するslotを閉じる。
- RV64 shellに`rm <path>`を追加（`unlink_file`を呼び出す）。

## guest + harness

- `guest/src/bin/file_unlink.rs`: create+write→unlink→read-fd失効
  （`EBADF`）→再`open`が`ENOENT`→同名`create`でslot回収を確認→
  内容をstdoutへ→directoryの`unlink`が`EISDIR`、不在pathが`ENOENT`
  を返すことを確認→exit(42)。
- `xtask`:`TestKind::FileUnlink`（filter`file-unlink`）、phase総数39。
- shell QEMUテスト:`rm "Long File Name.txt"`後の`ls`が当該fileを
  表示しないこと、`cat`がnot foundを返すことをtranscriptへ追加。

## 非目標

- `rmdir`（directory削除）、`rename`、fdのPOSIX式存続、
  fsck的な孤立cluster回収、削除のjournal化。
- LFN名での`create`（変更不能名は`EINVAL`のまま）。

## 検証

- host test:entry+LFN列の`0xe5`化、slot再利用、chain解放、
  破損chainの非破壊的失敗、削除済み名の`NotFound`、spc>1をまたぐ
  LFN runの削除。
- `cargo xtask test file-unlink`、shell transcript、全39フェーズ。
