# FAT32 long file names (LFN)

## 目的

`ls`がLFNを実名で表示し、`cat`/`ls`のpath要素がLFNと8.3 aliasの
両方で解決できるようにする。RV32はIMEM予算の関係で対象外（8.3 flatを維持）。

## 設計

### `DirEntry`（`kernel/src/storage/fat32.rs`）

```rust
pub struct DirEntry {
    name: [u8; 255],       // 表示名。有効なLFNがあればそれ、無ければ8.3
    name_len: u8,
    short_name: [u8; 11],  // alias照合用のraw 8.3
    first_cluster: u32,
    size: u32,
    directory: bool,
}
```

`entry_short_name`関数は廃止し、格納した`short_name`を直接使う。

### LFN収集（walk_dir内）

- attribute `0x0f`のrecordを`parse_dir_entry`へ渡す前にwalk loopが
  interceptし、`PendingLfn`へ積む。`0xe5`（deleted）はpendingをresetする。
- seq検査：`0x40`flag付きが最終chunk（最初に来る）で、その後は
  seq N-1..1と連続していること。非連続・chunk数>20・buf超過・非ASCII
  （0x20..=0x7e以外のUCS-2）は無効化し、8.3名へfallback。
- `apply`は直後のshort entryのraw 11-byte nameに対してchecksum
  （rotate-right累積和）を照合し、一致すれば表示名を差し替える。
  試行後は必ずresetする。
- `PendingLfn`は`riscv32`ではZST+no-op実装とし、walk loop自体は
  両target共通の無条件コードにする（rv32のcode/stack costは0）。

### path照合

- `find_entry_in`は`part: &str`を受け、`matches_component`で
  `eq_ignore_ascii_case(part, entry.name())`または
  `normalize_input_name(part) == entry.short_name`を判定する。
- `resolve_path`の要素検証をLFN向けに緩める：非空・`.`/`..`以外・
  全byteが0x20..=0x7e・`\\`不可。`A..TXT`のような内部dotはLFNとして
  有効（存在しなければ`NotFound`）。RV32側は`read_root_file`の
  8.3検査が従来通り`InvalidName`を返す（target間でerrorが異なる点は
  spec上の了承差異）。

### xtask / QEMU

- disk imageのrootに`Long File Name.txt`（short alias `LONGFI~1.TXT`、
  LFN 2 chunk）を追加。checksumはkernel側と同じ式をxtaskで複写。
- shell scriptに`cat Long File Name.txt`を追加し、transcriptで
  `ls`の長い名前表示と`cat`の内容を照合する。

## 非目標

- 255文字超の切り詰め挙動の細かい規定（buf超過は単に8.3 fallback）。
- `.`/`..`の解決、書き込み、UTF-8/非ASCII名。

## 検証

- host test：LFN名の列挙、LFN名でのread、8.3 aliasでのread、
  checksum不一致時の8.3 fallback、非連続seqのfallback。
- `cargo xtask test shell`で実機transcript照合。
- RV32 releaseがIMEMに収まること（現margin ~250B、増分はZST設計で~0）。
