# spec: `readdir` syscall — dir列挙をguestへ

## 背景

guestは`stat`でfile/directoryを判別できるが、directoryの中身を
列挙する手段がない。kernel shellの`ls`は`for_each_entry`を直接
呼ぶが、guest syscallとしては同じ情報が公開されていない。

## ゴール

`readdir`を追加し、pathで指定したdirectoryのentryをindex順に
1件ずつ返す。kindとnameを1 callで返すため、固定長`DirEnt`構造を
user bufferへcopy-outする（`stat`の`Stat`パターンを踏襲）。

## ABI

- `Readdir = 20`：`a0`=path pointer、`a1`=path length、
  `a2`=index、`a3`=out pointer。
- `a1`=0はroot directoryを意味する（`for_each_entry`の`""`→root
  契約を踏襲。rootを指す`.`や`/`名は`is_valid_component`が拒否
  するため、空pathが唯一のroot指定）。
- 戻り値：entryがあれば`DIRENT_LEN`（`read`系のbyte-count規約）、
  indexが末尾を越えれば0（`read`のEOF規約）、負はerrno。
- `DirEnt`（LE、計`DIRENT_LEN`=263 byte）：
  `name_len: u32`、`kind: u32`（`STAT_KIND_*`を再利用）、
  `name: [u8; 255]`。`name_len`は`name`内の有効byte数で、
  残りは0で埋める。guestは`name[..name_len]`を読む。
- 検証規約は`stat`と同じ：pathのEFAULT/EINVALとout rangeの
  `check_user_writable_range(DIRENT_LEN)`をsourceのside effect
  より先に確定する。

## 実装

- `abi/src/syscall.rs`：`Readdir = 20`、`DirEnt`、`DIRENT_LEN`、
  `DIRENT_NAME_LEN = 255`、serialize/parse往復test。
- `fat32.rs`：`entry_at(path, index) -> Result<Option<DirEntry>,
  FatError>`。`for_each_entry`と同じ解釈（`""`→root、file→
  `NotDirectory`）でdirを解決し、`walk_dir`の早期終了で
  index番目を返す。超過は`None`。
- `syscall.rs`：`ControlSource::readdir(path, index) ->
  Result<Option<DirEnt>, isize>`（default `ENOSYS`）。
  `dispatch_readdir`：path（len 0許容→root）→out検証→source→
  `Some`ならserializeして`ReadComplete`、`None`なら`a0`=0。
- `control.rs`：storage sessionの`entry_at`へ委譲し`DirEntry`を
  ABIの`DirEnt`へ写像（`DirEntry.name()`のbyte列を`name`へ複写）。
  context不在は`ENOSYS`。

## 検証

- host test：
  - ABI：番号20、`DIRENT_LEN`、serialize往復、name zero-fill。
  - fat32：`entry_at`の順序・index超過`None`・file`NotDirectory`・
    `""`→root・不在`NotFound`。
  - dispatch：`ReadComplete`とbyte列照合、index超過`a0=0`、
    空path→root到達、out EFAULT（source未到達）、errno透過、
    default source`ENOSYS`。
- guest `file_readdir`：rootの3件（HELLO.TXT→file、DOCS→dir、
  `Long File Name.txt`→file、LFN名25 byte）をindex順に確認、
  `DOCS`の2件（NOTE.TXT、CHILD.ELF）を確認、index 2で0、
  file path`ENOTDIR`、不在`ENOENT`、out=0`EFAULT` →
  `readdir verified`、exit 42。
- xtask：`file-readdir` phase、全46フェーズ。

## 非目標

- directory fdや`opendir`/`closedir`のhandle（fd modelはfileのみ。
  index指定のstateless列挙はO(n²)だが教材として明示する）
- entryのtype以外のmetadata（`stat`との組み合わせで得られる）
- shell側の変更（shellはkernel内で`for_each_entry`を直接使う）
- `.`/`..`の列挙（`walk_dir`の既存契約で除外される）
