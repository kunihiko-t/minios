# `rename`（同一directory内のfile名変更）

2026-09-16

## 背景

file lifecycleは`create`/`open`/`read`/`write`/`lseek`/`pread`/`pwrite`/
`unlink`/`close`まで揃った。残る基本操作として`rename`を追加し、
dir entryの「内容を保ったまま名だけを変える」経路を教える。

## 目標

- `Fat32::rename_file(old_path, new_path)`：同一directory内でentryの
  8.3名を書き換える。
- syscall `Rename = 12`：`a0=old_ptr, a1=old_len, a2=new_ptr, a3=new_len`。
- 新errno `EXDEV = -18`：新旧の親directoryが異なる移動は非対応として
  拒否する。
- guest `file_rename` + QEMU phaseで実機往復を検証する。

## 設計

### FAT32層（`kernel/src/storage/fat32.rs`）

`FatError`に`CrossDirectory`を追加。

`rename_file(old_path, new_path) -> Result<Option<(u32,u32)>, FatError>`:

1. 両pathの全要素を`is_valid_component`で検証し、`new_path`の最終要素を
   `to_short_name`で8.3正規化（長い名前・小文字は`create`と同じく
   `InvalidName`）。
2. `resolve_path(old_path)`。directoryは`IsDirectory`で拒否（dirの
   `rename`は`..`更新が要るため非対象）。
3. `new_path`の親dirを`resolve_path`で解決（rootなら`root_cluster`）。
   親がfileなら`NotDirectory`。`loc.dir_head`と一致しない場合は
   `CrossDirectory`。
4. 同名（正規化8.3名）の既存entryを`walk_dir`で照合：
   - sourceと同一の物理位置ならno-op成功（`rename("A","A")`）。
   - 既存entryがdirectoryなら`IsDirectory`。
   - 既存fileならPOSIX置換規約：chainを`chain_tail`で検証してから
     write phaseで削除し、戻り値へその物理位置を乗せる。
5. write phase（全検証後に実施）：
   - source entryの直前LFN runを削除（recordのみ、`0xe5`化）。
   - 置換対象がいれば、そのLFN run + entryを`0xe5`化しcluster chainを
     解放（`unlink`と同じ手順）。
   - source entryのname byteを新8.3名へ書き換えてsector write-back。
6. 戻り値は`Option<(dir_cluster, dir_index)>`：置換で消したtargetの
   物理位置。callerはそのentryを指すfdを`revoke_file_fds`で失効させる。

`lfn_run_start`を`lfn_run_bounds`へ拡張し、runの先頭と末尾record位置
を返す（LFNなしなら両端ともentry位置）。`unlink`はstartだけ使い、
`rename`はrun部分のみを`mark_deleted_range`へ渡す。

### fd semantics

- sourceのfdは`dir_location`不変（entryは同じ物理位置に残る）のため
  **有効のまま**——POSIXの「open fileはrenameを生き残る」に一致。
- 置換で消えたtargetを指すfdは`unlink`と同じく即座に失効する。

### syscall層（`kernel/src/user/syscall.rs`）

- `ControlSource::rename(old_path, new_path)`、default `ENOSYS`。
- `dispatch_rename`：2個のpathを別々の`[u8; MAX_PATH_LEN]` bufferへ
  copyするため、`copy_user_path`を`(ptr, len)`を引数に取る
  `copy_user_path_at`へ一般化。両pathの`EINVAL`（長さ）→`EFAULT`
  （copy）→`EINVAL`（UTF-8）をsource呼び出し前に確定する。

### bin層（`kernel/src/control.rs`）

- `UartControlSource::rename`を`FILE_STORAGE` sessionへ委譲。
- `fat_errno`に`CrossDirectory => EXDEV`を追加。
- `rename_file`が`Some(loc)`を返したら`revoke_file_fds`を呼ぶ
  （sourceのfdはloc不変で残る）。

### guest + xtask

- `guest/src/bin/file_rename.rs`：`REN.TXT`をcreate→write→close→
  `rename(REN.TXT→REN2.TXT)`→旧名`open`で`ENOENT`→新名readで内容
  照合→`EXIST.TXT`をcreate→`REN2.TXT`を`EXIST.TXT`へrename（置換）
  →`EXIST.TXT`読み戻し→directoryへのrename`EISDIR`→`DOCS/X`への
  rename`EXDEV`→rename中のfdが有効であること→exit(42)。
- `TestKind::FileRename` + `file-rename` phase + frame列verifier。

## host test

- 同一dir rename（entry位置不変・name更新・内容維持）
- 同名no-op
- 既存fileへの置換（target chain解放 + 戻り値loc）
- LFN fileのrename（LFN run削除 + 8.3名で再命名）
- directory拒否・cross-dir拒否・8.3化不能名拒否
- dispatch：2path copy、`EFAULT`/`EINVAL`規約、source結果の`a0`反映

## 非目標

- directoryのrename（`..` entryの更新が必要なため別課題）
- 別directory間の移動（`EXDEV`で明示的に拒否）
- LFN名でのrename（`create`と同じ8.3規約のまま）
