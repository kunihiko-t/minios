# pipe syscall — process間のbyte channel

## 背景

fd継承が入ったことで、spawnしたchildはparentのopen fileを同じfd番号で
読めるようになった。次の自然な構造は、fileではなくkernel管理のbounded
bufferを介してprocess間へbyteを流す`pipe`である。これはstdin・pid終了に
続く3つ目のblock条件（`BlockedOnPipe`）を教える恰好の題材であり、
file API・spawn・waitpid・fd継承の総動員デモになる。

## 目標

- `pipe` syscallでread/write両端のfdを生成する。
- pipe本体はkernelが所有するbounded ring buffer（256 byte、最大4本）。
- fd継承により、spawnしたchildはparentが作ったpipe端をそのまま使える。
- read側は空ならblockし、write側が全て閉じればEOF（0）を返す。
- write側は満杯ならblockし、read側が全て閉じれば`EPIPE`を返す。
- 端を閉じたprocessやexitしたprocessのfdは直ちにpeer側の
  EOF/EPIPE判定へ反映される。

## 設計

### ABI

- `Pipe = 22`：`a0`はwritableな8 byteのuser pointer。成功時は
  `[read_fd: u32, write_fd: u32]`をLEで書き込み、`a0`に8を返す
  （`stat`/`readdir`と同じbyte-count規約）。
- 新しいerrno：`EAGAIN = -11`（内部signal。control層がcallerを
  `BlockedOnPipe`へmarkした上で`Err(EAGAIN)`を返すと、dispatchが
  `sepc`をecallへ戻して`Blocked`を返す。guestへは表面化しない）、
  `EPIPE = -32`（read端の全てが閉じたpipeへのwrite）、
  `ESPIPE = -29`（pipe fdへの`lseek`/`pread`/`pwrite`）。
- `STAT_KIND_PIPE = 2`：`fstat`がpipe fdへ返すkind。sizeは常に0。

### kernel object

`kernel/src/pipe.rs`に`Pipe`（head/len/dataのring buffer、
`PIPE_CAPACITY = 256`）と`PipeTable`（`[Option<Pipe>; MAX_PIPES = 4]`）を
置く。`ProcessTable`が`pipes: PipeTable`を所有する。

**生死は参照計数ではなく派生する**：pipeの端はfd tableのslotに
`FdEntry::Pipe { id, write }`として記録され、あるpipe idのliveな端数は
全processのtableを走査して求める。`pipe_alloc`は空slotかlive端数0の
slotを再利用するため、closeやexitでの明示的なfree処理は要らない
（fdはprocessとともに死に、scanが0を報告したslotは次回allocで回収）。
この方式ではincrement/decrementの取りこぼしが構造的に起きない。

### fd table

slotの中身を`FdEntry` enumへ変更する：

- `FdEntry::File(FileFd)` — 従来のfile fd（desc/offset/writable）。
- `FdEntry::Pipe { id: usize, write: bool }` — pipeの端。
  `write`は方向を示し、fd 1個がread専用かwrite専用かを決める。

`FileFd`自体は不変。`fd_mut`は`&mut FdEntry`を返し、file専用の
accessor呼び出しはcontrol側がmatchして分岐する。`alloc_pipe_fd(id,
write)`を追加し、`revoke_fd_at`/`relocate_fd_at`はFileのみに効く。
`FdEntry`は`Copy`のままなので`spawn`のsnapshot継承は無変更で効く
（childの端はliveness scanに自動計上される）。

### block/wake

`ProcessState::BlockedOnPipe(usize)`を追加。`block_on_stdin`は
runnable時のみ遷移する既存guardにより上書きしない。

- `pipe_read`：pipeにdataがあれば`min(len, avail)`を読み同pipeの
  waiterをwakeして`Ok(n)`。空でwrite端がliveならcallerを
  `BlockedOnPipe(id)`へmarkして`Err(EAGAIN)`（→Blocked）。write端が
  0なら`Ok(0)`（EOF）。
- `pipe_write`：read端が0なら`EPIPE`。空きがあれば
  `min(len, free)`を書きwaiterをwakeして`Ok(n)`。満杯ならcallerを
  `BlockedOnPipe(id)`へmarkして`Err(EAGAIN)`。data長0は常に`Ok(0)`。
- `close`：pipe端を閉じたら同pipeのwaiterを全てwakeする
  （EOF/EPIPE条件が変わり得る）。
- `wake_on_exit`：`BlockedOnPid(pid)`に加えて`BlockedOnPipe(_)`の
  waiterも全てwakeする。exitしたprocessのfdはtableから消えるため、
  再dispatchしたwaiterのscanがEOF/EPIPEを見る（疑似wakeは再blockへ
  戻るだけで安全）。
- `wake_all_blocked`（stdin到着）とtimer preemptionは既存の
  「非runnableをskip/起こす」規約にそのまま乗る。

### syscall経路

- `dispatch_pipe`：out pointerの`EFAULT`をsourceより先に確定し、
  `source.create_pipe()`の結果を8 byteへserializeして`ReadComplete`。
- `dispatch_read`/`dispatch_write`：`read_fd`/`write_fd`の
  `Err(EAGAIN)`をBlockedへ変換するarmを追加。
- `ControlSource::create_pipe() -> Result<(usize, usize), isize>`を
  追加（defaultは`ENOSYS`）。
- `read`/`write`のwrite/read逆向きのpipe端は`EBADF`。

### trap窓accessor（`main.rs`）

- `create_pipe`：`table.pipe_alloc`（満杯は`ENOMEM`）→ callerへ
  read/write両端を`alloc_pipe_fd`（fd満杯は`EMFILE`でread端をrollback）。
- `pipe_read`/`pipe_write`：`ProcessTable`の同名opへ委譲し、
  `Blocked` outcomeを`EAGAIN`へ写像する。
- `close_file_fd`：閉じる前にentryがpipe端かをpeekし、閉じた後に
  `wake_pipe_waiters(id)`を呼ぶ。

## エラーとエッジケース

- `pipe`のfd table満杯は`EMFILE`（片方だけ割り当てた状態はrollback）、
  pipe slot枯渇は`ENOMEM`、out pointer不正は`EFAULT`、process context
  なしは`ENOSYS`。
- `read`/`write`/`close`のfd規約（未割当`EBADF`、len上限`EINVAL`）は
  pipe fdにもそのまま適用される。
- `pread`/`pwrite`/`lseek`へのpipe指定は`ESPIPE`、`fstat`は
  `STAT_KIND_PIPE`/`size=0`。
- `spawn`したchildは両端を継承する。片端だけを使うならchild側で
  closeするのがguestの作法となる。
- `exec`はfd tableを保持するためpipe端も引き継ぐ。

## 検証

### host test

- `Pipe`：wrap-aroundを含むread/write、満杯・空でのpartial I/O。
- `ProcessTable`：pipe_allocの再利用、pipe_read/writeのdata・
  Blocked・EOF・Broken経路、wake_pipe_waiters、exit時のpipe waiter
  wake、継承childの端がlivenessに計上されること。
- dispatch：`pipe`のfd pair copy-outと`EFAULT`/`ENOSYS`、
  read/writeの`EAGAIN`→`Blocked`変換と`sepc`巻き戻し。

### QEMU検証（`file-pipe` phase）

disk fixtureに`DOCS/PIPECH.ELF`（手組みELF64、`read(3, sp-64, 64)`→
11 byteならstdoutへ写して`exit(42)`、失敗時`exit(70)`）を追加する。

guest `file_pipe`は:

1. `pipe`でfd [3, 4]を得る。null outの`EFAULT`を確かめる。
2. `fstat(3)`が`STAT_KIND_PIPE`、`lseek`が`ESPIPE`、read端への`write`
   とwrite端への`read`が`EBADF`を返すことを確かめる。
3. `spawn("DOCS/PIPECH.ELF")`でchildを起こし、`write(4,
   "pipe-bytes\n", 11)`してから`waitpid`で回収する。
   childは継承したfd 3から11 byteを読みstdoutへ写す。
4. `close(4)`後の`read(3)`がEOF 0を返すこと（全write端のclose伝播）、
   2本目の`pipe`でslot再利用→`close(3)`→`write(4)`が`EPIPE`を返す
   ことを確かめてから`pipe verified`をstdoutへ出し`exit(42)`。

`waitpid`でparentがblockするため、childのstdout+Exitはparentの
markerより必ず先——exact順序照合が可能。

## 非目標

- `pipe2`のflag、O_NONBLOCK、PIPE_BUF atomicityの保証（writeは
  常にpartial可）。
- poll/select的な多重待ち。1 processが同時に待てる条件は1つ。
- 複数processからの同時read/writeの順序保証。
