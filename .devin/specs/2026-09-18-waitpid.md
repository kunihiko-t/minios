# `waitpid` syscall — child終了statusの受け渡し

## 目的

`spawn`で起動したprocessの終了codeを、待つprocessが回収できるようにする。
stdin待ち以外でprocessをblockする初めての条件（別processの終了）であり、
schedulerのblock/wake機構を一般化する。

## ABI

- `Waitpid = 17`。`a0` = 対象pid。戻り値はchildの終了code（非負）か
  負のerrno。
- `ECHILD = -10`：対象pidが自分自身、存在しない、既に回収済み、または
  異常終了でstatusを持たない。
- `EINVAL`：wait連鎖が呼び出し側へ戻るcycle。
- `ENOSYS`：process context無し（rv32・default実装）。

## 意味論（POSIXの教育用縮約）

- 対象がexits ledgerに記録済み → 記録を消費してcodeを返す（reap）。
- 対象がlive → 呼び出しprocessを`BlockedOnPid(target)`へ。対象終了時に
  wakeし、同じecallが再実行されてcodeを返す（`read`のBlocked再実行
  モデルと同じ）。
- 対象が自分自身・存在しない・既reap・異常終了（status無し）→ `ECHILD`。
- 複数waiter可：対象終了で全員wake、先に再dispatchした1つだけがcodeを
  得て、残りは`ECHILD`。
- spawn以外の全process終了でもledgerへ記録する。ledger上限`MAX_PROCS`件、
  超過は最古をdrop（そのpidへのwaitpidは`ECHILD`）。
- 親終了後のchildは継続実行（reparentingは非目標）。

## 実装

### `Process` / `ProcessTable`

- `ProcessState::BlockedOnPid(usize)`を追加。`block_on_stdin`は
  runnable時のみ遷移するよう変更（controlが先にpid blockをmarkする
  ため、run loopの`block_on_stdin`呼び出しで上書きされない）。
- `block_on_pid(target)`／`waiting_on()`。
- `exits: Vec<(usize, u32)>` ledger、`record_exit`/`take_exit`/
  `wake_on_exit(pid)`/`block_waitpid(caller, target)`（live・self・
  cycle検査を集約）。
- run loopのexit経路で`record_exit`＋`wake_on_exit`。fatal経路は
  `wake_on_exit`のみ（waiterは`ECHILD`）。

### dispatch / control

- `dispatch_waitpid`：`source.waitpid(pid)`が
  `Ok(Some(code))`→a0へcode、`Ok(None)`→`SyscallFlow::Blocked`、
  `Err`→errno。
- `ControlSource::waitpid`：exits確認→liveなら`block_waitpid`でmarkして
  `Ok(None)`、cycle/self/不在→errno。

## 検証

- host：exits記録・reap・二重reap・self/不在/cycle拒否・全waiter wake・
  ledger上限・blocked分類のpick_next skip。
- guest `file_waitpid`：spawn→waitpid(1)→42、再waitpid→ECHILD、
  self/不明pid→ECHILD。childのoutput+exitが親の`waitpid verified`
  より必ず先＝確定的なframe列でexact照合（blockingの直接証拠）。
- 全43+1フェーズの`cargo xtask check`。
